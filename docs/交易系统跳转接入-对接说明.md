# 交易系统跳转审计平台 · 接入对接说明

我方（交易系统）已按 Hub 新的一次性交接协议改造完成交易侧代码，链路为：

```
浏览器 → /entry/start → 交易后端授权 → /hub/web/launches → /entry 建立会话
```

需要贵方（Hub 侧）配合以下事项，**均不涉及改代码**。

---

## 一、在 `/ops` 配置页填写（“交易系统接入”分组）

| 页面标签 | 配置键 | 填写值 |
| --- | --- | --- |
| 中台公开地址 | `web.public_origin` | `http://10.112.191.163:15140` |
| 交易系统授权地址 | `web.trading_authorize_url` | `http://10.112.191.163:3000/api/pam/authorize` |
| 使用 HTTPS 安全会话 | `web.secure_cookie` | `false`（当前 HTTP 内网联调；正式上 HTTPS 后改回 `true`） |

说明：

- `web.secure_cookie=true` 时，`public_origin` 与 `trading_authorize_url` 都必须是 `https://`，否则保存报错，故联调阶段先关闭。
- 交易系统授权地址保存后**热生效**，无需重启。
- 中台公开地址如有需要，请重启 `pam-hub` 使配置生效。

---

## 二、需要贵方导出并安全下发给我方

- **交易后端接入凭据**（`security.trading_entry_token`）：在“服务凭据”里点“备份接入凭据”，重新验证运维密码后导出。
- 我方将其配置为交易后端的 `X-Trading-Token`，用于调用 Hub 的 `GET /hub/web/requests/{request_id}` 与 `POST /hub/web/launches`。

---

## 三、中台查看范围（已按新版确认）

新版 Hub 为全局只读总览：`/entry/start` **无须合同编号**，可选的 `pcc_contract_id` 仅作业务定位提示，不限制查看范围。`GET /hub/web/requests/{request_id}` 返回 `mode=reader`、`access=global_read`、`pcc_contract_ids=null`，交易后端只需校验“用户已登录且具有中台访问资格”，**无须逐合同查权限**，也无须调用 PCC 批准用户。

我方按此实现：发起跳转不再强制合同号，改为 `GET /hub/web/requests/{request_id}` 校验 `mode=reader` 后直接换发授权。

---

## 四、我方回调接口（对应上面的交易系统授权地址）

- 地址：`GET http://10.112.191.163:3000/api/pam/authorize`
- 接收参数（由 `/entry/start` 303 带回）：`request_id`、`mode`、`redirect_uri`（可选 `pcc_contract_id`）
- 处理流程：
  1. 校验交易用户登录态与中台访问资格
  2. 使用 `X-Trading-Token` 调用 `GET /hub/web/requests/{request_id}`，确认 `mode=reader`
  3. 调用 `POST /hub/web/launches`，请求体 `{ "request_id": "...", "subject": "trade:<用户名>" }`，换取 `launch_url`
  4. 303 浏览器跳转到 `launch_url`

---

## 五、请贵方确认

1. 上述三项配置保存成功，`/entry/start` 不再返回 503。
2. `http://10.112.191.163:3000`（交易后端）在贵方侧可达（此前部署检查时该端口不可达）。
3. 交接依赖浏览器绑定 Cookie，联调时请在**同一个浏览器**内完成整个跳转，不要将链接复制到其他浏览器打开。
