## 发现的问题

### 1. 跨订单交付可能互相删除 VM

位置：`backend/tee/routes.js:780`、`:830`，`backend/tee/hostVmCleanup.js:113`。

每次执行交付都会列出并清理海光主机全部 VM。现有锁和额度占位只约束单个订单；不同订单可以分别进入交付。第二笔订单的清理可能删除第一笔刚建好、等待买方模型或正在计算的 VM。密钥流程串行化不能覆盖整个 VM 生命周期。

建议：针对这台单业务入口主机建立跨订单、可跨进程的占用约束，覆盖清理、创建、等待模型、计算及释放；或者改为有独立入口的多 VM 隔离方案。不能仅增加单订单重复点击保护。

### 2. 数据库迁移文件漏合入

仅副本保留：

- `backend-logic-preview/sql/2026-10-06-tee-csv2-adaptation.sql`
- `backend-logic-preview/sql/2026-10-07-tee-contract-model-hash-delivery-limit.sql`

当前数据库已有相关字段，因此这不是当前数据库的缺列故障。但只按正式目录重新部署或恢复到较老数据库时，会漏掉证明、清理和合约次数字段。正式 README 也未同步副本新增的部署及验收说明。补齐时应一起核对模型哈希字段的前置迁移，不能假设这两个增量脚本能独立建立完整数据库。

### 3. 测试和验收资源漏合入

正式目录缺少副本的 15 个 `tests/tee*.test.js`、相关 fixtures、`scripts/csv2-e2e-test.js` 及测试记录；前端也缺少副本中的 TEE 回归测试。运行代码已合入，但正式版无法直接复用原有验收命令。

本次将已有测试复制到 `/tmp/tee-formal-audit`，让其引用正式版代码和页面，逐文件运行：后端 **68 项通过**，1 项写数据库集成测试未开启；前端 TEE 和 deliveryUi **44 项通过**。其中包含协议、加解密、额度策略和编排单元测试，也包含源码结构检查；它们不是完整真实 HTTP 交付验收。

### 4. 运行数据未全部迁离副本

`tee_asset_materials` 中两条 `csv2-asset-*` 测试素材记录的绝对路径仍指向 `backend-logic-preview/storage/tee-assets`。

订单 `528`、`530`、`531` 的部分加密结果只存在副本结果目录。当前 `530`、`531` 和 `528` 最新成功轮次仍可通过数据库缓存及当前密钥兜底显示可下载；不代表结果文件已迁移。`528` 第 2、4 轮 SUCCESS 在正式接口中为 `resultAvailable=false`。这些旧文件仅有密文，没有完整下载归档，不能保证仅复制文件即可恢复历史轮次。

两个普通哈希资产的素材路径已在正式目录，订单 `543` 也已有正式结果和下载归档。清除副本前应清点测试记录、素材、密文与对应轮次解密材料，避免误删仍被引用的数据。

### 5. 现存合约不能直接用来重跑

数据库共 47 份 TEE 合约，42 份缺模型哈希及交付次数，当前无未过期合约。旧合约在新模型/合约协议下无法完成校验；订单 `543` 也已过期且 1 次额度已耗尽。

新验收应创建有效期内的新订单，购买阶段提交 `.c` 模型，确认形成完整合约，交付阶段再次提交相同模型。不要通过修改旧合约或重置成功次数绕过限制。

### 6. 运行身份和权限需要随部署固定

当前 root 进程能够使用受限目录；普通 super 用户不能读取 `backend/.tee-host-ssh-secret`，不能访问 `storage/tee-requests`，也不能写 root 所有的 `storage/tee-results` 根目录。直接按普通用户启动的方式切换服务，可能在 SSH 清理、买方权重保存或结果归档阶段失败。

建议明确服务账号，并按账号授予最小必要目录权限，保留私钥、密钥文件及下载归档的私有权限。

### 7. TEE 接口缺少服务端买卖方权限校验

`registerTeeRoutes` 的模型、交付、结果与密钥路由没有登录及订单归属中间件；前端路由限制不能替代后端校验。源码中的 `/key-file` 会按交易号返回私钥及密钥封装，`/attempt-result` 仅绑定交易号和轮次，并未验证调用者为买方。应在正式交付验收中补充买卖双方身份和订单归属测试。
