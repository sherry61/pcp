## 2. 这次最重要的教训

### 2.1 “更新内容”不等于“重做格式”

这次最大的问题是：用户要求更新内容，我却把原本已经成型的版式整体重做了一遍。

正确做法：

1. 先确认旧版是否是模板基线。
2. 只改用户明确要求改的部分。
3. 保留原有字体、字号、行距、表格色、题注、页眉页脚和目录样式。
4. 不要因为“我觉得更好看”而替换整套视觉规范。

对于操作手册这类交付物，**版式稳定性本身就是质量的一部分**。

### 2.2 先研究旧文件，再动手

旧版 docx 里已经包含了完整的样式体系：

- 正文 12pt，宋体 / Times New Roman
- 1.3 倍行距
- 首行缩进 2 字符
- 一级标题 16pt 黑体
- 二级标题 14pt 黑体
- 表头深青色 `1B6B7A`
- 表头白色微软雅黑加粗
- 表格浅青色细边框
- 图题、表题灰色加粗 10.5pt
- 页眉页脚 9pt 灰色

这些都应该直接从旧文件继承，而不是重新定义。

### 2.3 字体问题不能只看 PDF

这次标题在 Word 里显示成 MS Gothic，根因有两个：

1. 段落样式的 `rFonts` 里同时存在：

```xml
w:asciiTheme="majorHAnsi"
w:eastAsiaTheme="majorEastAsia"
w:ascii="黑体"
w:hAnsi="黑体"
w:eastAsia="黑体"
```

Word 会优先使用主题字体，导致中文标题落到 MS Gothic。

2. 标题的关联字符样式没有同步修改：

```text
Heading 1 Char
Heading 2 Char
Heading 3 Char
```

这些字符样式里仍然残留主题字体。

正确做法：

- 标题段落样式只保留：

```xml
<w:rFonts w:eastAsia="黑体"/>
```

- 删除 `asciiTheme`、`eastAsiaTheme`、`hAnsiTheme`、`cstheme`
- 删除 `ascii="黑体"`、`hAnsi="黑体"`
- 同步修改 `Heading 1 Char / 2 Char / 3 Char`
- 标题里的数字使用 Times New Roman，中文使用黑体

注意：PDF 是 LibreOffice 在 Linux 上生成的，缺少黑体时会回退到 Noto Sans CJK。**不能只根据 PDF 判断 docx 的字体设置是否正确**，必须检查 `word/styles.xml`。

### 2.4 项目符号不要用 Symbol 字体

Word 的 `List Bullet` 样式默认使用：

```xml
<w:rFonts w:ascii="Symbol" w:hAnsi="Symbol"/>
<w:lvlText w:val=""/>
```

`U+F0B7` 是 Symbol 字体的私用区字符。在某些 Office / WPS / 系统字体环境下，它会显示成黑色小方块。

正确做法：

- 不使用 `List Bullet` 自动编号
- 直接写入普通字符 `•`
- 使用悬挂缩进排版

这样不依赖 Symbol 字体，跨环境稳定。

### 2.5 左侧黑方块和 Symbol 方块是两回事

Word 中左侧页边距出现的小黑方块，通常表示该段设置了：

- 与下段同页（keep with next）
- 段中不分页（keep lines together）

它们是非打印编辑标记，只在打开“显示编辑标记”时出现。

如果用户不希望看到这些标记：

1. 文档中移除不必要的 `keepNext/keepLines`
2. 或者让用户关闭 Word 的“显示编辑标记”

关闭方式：

```text
开始 → 段落 → 显示/隐藏编辑标记（¶）
```

快捷键：

```text
Ctrl + Shift + 8
```

注意：关闭编辑标记后，段落末尾的 `↵` 也会一起消失。

### 2.6 步骤序号必须用悬挂缩进 + 固定制表位

如果只写：

```text
步骤1　填写……
步骤10　填写……
```

会出现：

- 步骤 1 和步骤 10 后面的正文起始位置不同
- 换行后的文字回到左缩进位置，和正文对不齐

正确做法：

- 左缩进 1.5cm
- 首行缩进 -1.5cm
- 在 1.5cm 处设置制表位
- 标签和正文之间使用 Tab

这样：

- 所有步骤号从左边距开始
- 所有正文从 1.5cm 开始
- 换行后的文字也与正文左边缘对齐

### 2.7 术语要统一，不要中英混排失控

这次术语表出现过：

```text
HE（同态加密）
长安链（ChainMaker）
```

中英文顺序不一致，读者会感到混乱。

统一规则：

- 中文术语在前，英文缩写放括号里
- 示例：

```text
同态加密（HE）
代理重加密（PRE）
联邦学习（FL）
多方安全计算（MPC）
可信执行环境（TEE）
以太坊兼容链（EVM）
```

产品名如“长安链”不要再加英文别名。

### 2.8 用户看不懂的内部术语要翻译

`PAM Hub` 这类词不应该出现在用户手册里。

应统一改成：

```text
审计中台
```

审计截图也要注意，不要把内部系统名称、侧边栏或页脚带进正式文档。

### 2.9 不要暴露演示账号和密码

操作手册不是测试说明，不应出现：

```text
buyer / 123
seller / 123
admin / 123
```

演示账号应放在独立的测试说明或交付说明中，不进入用户手册。

### 2.10 提示框不是越多越好

浅灰蓝底、左侧粗边框的提示框多了会显得杂乱。

现在已改为普通正文段落，只有必要信息保留“注意：”前缀。

如果后续需要强调，可以使用：

- 正常正文
- 加粗关键词
- 必要时使用简洁的表格

不要为了“好看”堆叠装饰性容器。

### 2.11 目录页码必须重新计算

每次调整内容、字体、图片、分页后，目录页码都可能变化。

维护流程：

1. 生成 docx
2. 转 PDF
3. 从 PDF 提取每一页的标题位置
4. 用实际页码回填目录
5. 再生成一次 docx
6. 再转 PDF
7. 对比目录页码和正文页码

不要手写目录页码，也不要依赖“更新域”提示。

### 2.12 孤行标题要用显式分页处理

移除 `keepNext` 后，可能出现标题落在页底、正文在下一页的情况。

正确做法：

- 在需要的位置插入显式分页
- 不要重新加回 `keepNext`，否则黑方块会回来

这次对以下位置做了显式分页：

- 第 5 章开头
- 5.3 节
- 8.3 节
- 附录 A

## 3. 当前手册规范

- A4
- 左边距 3.0cm
- 右边距 2.5cm
- 上边距 2.54cm

- 中文：宋体

- 字号：12pt
- 行距：1.3 倍
- 首行缩进：24pt
- 对齐：两端对齐
- 段后：4pt

### 3.3 标题

- 一级标题：16pt 黑体，深藏青色 `0A1628`
- 二级标题：14pt 黑体
- 三级标题：12pt 黑体
- 标题不使用主题字体
- 不使用 `asciiTheme / eastAsiaTheme`

### 3.4 表格

- 表头填充：`1B6B7A`
- 表头文字：白色、微软雅黑、10.5pt、加粗
- 表体文字：10.5pt、`1A1A1A`
- 上边框和下边框：深青色
- 内部横线和竖线：浅青色 `C8DDE2`
- 表格宽度：100%

### 3.5 图题和表题

- 10.5pt
- 加粗
- 灰色 `555555`
- 居中

### 3.6 项目符号

- 使用普通字符 `•`
- 不使用 Symbol 字体编号
- 使用悬挂缩进

### 3.7 步骤

- 悬挂缩进 1.5cm
- 制表位 1.5cm
- 标签和正文之间使用 Tab

### 3.8 页眉页脚

- 页眉：9pt 灰色微软雅黑，居中，底部细线
- 页脚：9pt 灰色，居中页码
- 目录页使用罗马数字页码
- 正文从第 1 页开始

## 4. 推荐维护流程

### 第一步：确认基线

- 确认当前 docx 是否是要保留的版式
- 不要重新设计
- 不要替换样式体系

### 第二步：只改内容

- 删除前端不可达的模块
- 更新角色和页面
- 更新截图
- 保持术语统一

### 第三步：生成文档

推荐使用 python-docx 或直接编辑 docx，但必须继承旧样式。

生成后检查：

```bash
soffice --headless --convert-to pdf --outdir docs \
  "docs/数字资产流通系统-用户操作手册-V1.2.docx"
```

### 第四步：检查字体

检查 `word/styles.xml` 中是否还有：

```text
asciiTheme
eastAsiaTheme
hAnsiTheme
majorEastAsia
MS Gothic
```

标题样式应该只有：

```xml
<w:rFonts w:eastAsia="黑体"/>
```

### 第五步：检查编辑标记

检查 `word/document.xml`：

```text
keepNext     0
keepLines    0
numPr        0
ListBullet   0
```

如果还有，确认是否确实需要。

### 第六步：检查目录

从 PDF 提取标题实际页码，回填目录，再生成一次。

验证：

```text
目录页码与正文页码不一致数量 = 0
```

### 第七步：检查内容

至少检查：

- 是否还有 `「」`
- 是否还有 `PAM Hub`、`ChainMaker` 等内部术语
- 是否暴露演示账号
- 是否还有前端不可达的模块
- 角色是否覆盖买方、卖方、监管方、审计方、管理员
- 截图是否来自当前系统

### 第八步：检查分页

确认没有标题单独落在页底。

如果有，插入显式分页，不要使用 `keepNext`。

## 5. 截图规范

- 使用当前系统的真实页面
- 使用 Chrome Headless + CDP 截图
- 登录后设置对应角色会话
- 隐藏 Toast 和调试信息
- 弹窗截图要裁剪，不要整页留大量空白
- 截图里不要出现内部系统名、测试账号、密码
- 审计相关截图要裁掉侧边栏和内部标识
- 图片宽度保持与旧版一致，约 13.76cm
- 裁剪后的弹窗图可适当缩小，避免占满整页

## 7. 后续建议

1. 把这份手册的样式作为固定模板，后续只替换内容，不再重做版式。
2. 维护一个术语表，新增术语先查表再写。
3. 截图统一使用 CDP 脚本，固定分辨率、角色和裁剪规则。
4. 每次改完都执行一遍验收清单。
5. 如果后续要交给其他人维护，建议同时保留：
   - docx 源文件
   - PDF 预览
   - 截图原图
   - 生成脚本或至少一份样式说明

## 8. 一句话总结

这次的核心教训是：

> 更新交付文档时，先尊重已有模板和版式，再谈内容更新；字体、项目符号、步骤缩进、目录页码这些细节，必须在 Word 和 PDF 两个层面分别验证。
